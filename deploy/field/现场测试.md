# 松灵杯 L1 / L2 现场测试包

适用环境为 Ubuntu 22.04 x86_64 和 ROS 2 Humble。使用组委会镜像中的 PiPER 与大白相机驱动。现场目录提供 Python 3.10 的离线依赖、CPU SAM2.1 与 YOLOE-26n 权重和 PiPER 运动学模型。包含 `setup-qwen.sh` 的目录还提供独立的 CUDA 12.8 运行环境和 Qwen3-VL-4B BF16 权重。

## 安装与标定

```bash
source /opt/ros/humble/setup.bash
# 如驱动位于独立工作区，再 source 组委会给的 install/setup.bash
./setup.sh
./setup-qwen.sh
```

第二条用于千问分类。当前 BF16 权重在 RTX 5090 上的逐个裁剪推理峰值约为 8.3 GiB，模型默认在启动时检查 12288 MiB 空闲显存。现场算力不足时可以显式选择 `--l2-category-backend rules` 走规则分类。

现场目录的 `field_calibration.yaml` 由打包时指定的文件生成。源码仓库中的模板须用工位对应的彩色内参、深度单位和手眼矩阵填充。矩阵将彩色光学坐标点变换到 PiPER 法兰，平移用米。核对 ROS 光学帧名、图像配准和观察位置。若使用已经校正且同样配准的图像流，按该流的 CameraInfo 填内参和空畸变数组。

相机驱动应开启深度到彩色的配准。现场提供的 DaBai DC1 彩色内参对应 640×480 原始流，640×400 原始深度须由驱动配准到彩色像素。彩色和深度必须使用同一光学帧、像素大小和时钟。固定相机应能看到取料区和三个完整目标区，初始关节姿态用作复查时的退避观察位。

## 按顺序测试

```bash
./run.sh probe --task l1 --dashboard-port 8773 --preview-seconds 30
./run.sh probe --task l2 --dashboard-port 8773 --preview-seconds 30
```

`probe` 只订阅反馈和图像，读取 PiPER 驱动的夹爪比例，不建立运动发布器。结果写到 `logs/<时间>_probe/report.json`，同目录含相机帧和识别证据。核对识别坐标、目标区与实际台面一致。

按现场流程使能机械臂并确认小幅移动方向和夹爪反馈，再运行任务。

```bash
./run.sh jog --joint 1 --delta-rad 0.03 --speed-percent 10
./run.sh l1 --dashboard-port 8773
./run.sh l2 --dashboard-port 8773
```

L1 默认同色投放。如果任务卡为每种颜色指定了不同区域，可用 `./run.sh l1 --l1-sort 'red=green,green=yellow,yellow=red'` 传入实际的一一对应关系。

L2 默认使用队伍指定的类别分区。

| 目标区 | 果蔬类别 |
| --- | --- |
| 黄色 | 香蕉 `banana`、土豆 `potato` |
| 绿色 | 黄瓜 `cucumber`、梨 `pear` |
| 红色 | 彩椒 `bell_pepper`、柿子 `persimmon` |

任务卡发生变化时可用 `--l2-sort` 传入新的 `类别=目标区` 列表。无法判定类别的目标会重新观察。

L1 使用三色方块和对齐深度。L2 把每个实例掩码裁剪图交给本地千问，限定为比赛六类、「其他」或「不确定」。程序校验候选编号和类别，按表选择目标区，再用 RGB-D 测量色区边界。程序在边界内找可达空位，放置后复查位置与稳定性。两项任务都通过关节反馈完成抓取和试提。夹爪宽度是夹持的间接证据，当前未完成裁判所需的独立视觉抬升证明。

L2 默认在 640×480 下使用 YOLOE-26n 快速分割。视觉提示来自仿真样本，候选须与当前深度前景唯一对应并通过抓取几何检查。未能确认的候选继续交给 SAM2.1。其他分辨率直接使用 SAM2.1。给 `probe` 或 `l2` 加 `--l2-model sam2` 可测试纯 SAM2.1 路线。

腕部相机先扫描常用观察位。目标只露出一部分时，程序利用可见深度调整视角，重新看到完整目标后才规划抓取。常用观察位找不到候选时，下一轮加入两侧较宽的观察位。固定相机回到可观测的退避姿态再拍，工位摆放须在相机覆盖范围内。日志记录每次换视角与尚未完成的目标数。

## 过程展示与留档

使用 `--dashboard-port 8773` 运行后，在同一台电脑打开终端打印的现场任务台地址。页面展示同帧腕部 RGB 和配准深度、带时间戳的识别分割叠图，以及每个目标的类别、目的区、抓取点和释放点。深度图用米制伪彩显示，黑色表示无效深度。任务台只读，运动由终端中的 ROS 2 程序执行。

`logs/<本轮目录>/process.html` 保留带编号的观测和进度，结束后可打开复查。现场页面与轮次进程同生命周期。`probe --preview-seconds 30` 会在只读检查后保留页面和相机订阅 30 秒。

`process_events.jsonl` 在识别时就写入队内编号、类别、目标区及对应观测帧。之后的抓放尝试、试提反馈和放置复查沿用同一编号。`probe` 的记录标为只读检查，正式轮次的识别从开始计时后记录。放置复查通过表示程序已根据 RGB-D 检查入区和稳定两秒。试提保持来自夹爪反馈，有效抬升由裁判核验。

## ROS 2 接口

| 默认话题 | 消息 | 用途 |
| --- | --- | --- |
| `/joint_states_single` | `sensor_msgs/msg/JointState` | 六关节反馈为弧度，`gripper` 为总开口米 |
| `/arm_status` | `piper_msgs/msg/PiperStatusMsg` | 检查驱动状态及故障码 |
| `/camera/color/image_raw` | `sensor_msgs/msg/Image` | `rgb8` 或 `bgr8` |
| `/camera/depth/image_raw` | `sensor_msgs/msg/Image` | 对齐到 RGB 的 `16UC1`、`mono16` 或米制 `32FC1` |
| `/joint_ctrl_single` | `sensor_msgs/msg/JointState` | 六关节目标和夹爪目标，按官方 Humble 驱动格式 |

本包从唯一控制订阅者的 ROS 参数服务读取 `gripper_val_mutiple`。反馈保持总宽度米，发布时按驱动比例转换。官方驱动将第七项 `velocity` 作为速度百分比。运行时必须保留实际工位的 ROS 域和命名空间。组委会话题与默认值不同可使用 ROS 2 重映射。

```bash
./run.sh probe --task l2 --ros-args \
  -r /joint_states_single:=/bench_a/joint_states_single \
  -r /joint_ctrl_single:=/bench_a/joint_ctrl_single \
  -r /arm_status:=/bench_a/arm_status \
  -r /camera/color/image_raw:=/bench_a/camera/color/image_raw \
  -r /camera/depth/image_raw:=/bench_a/camera/depth/image_raw
```

对 `jog`、`l1`、`l2` 使用同样的重映射。现场自定义驱动须兼容表中的消息和单位。驱动保持现场原有使能与急停流程。

## 反馈与停止

程序检查图像和关节时间同步、驱动状态、命令话题是否被其他节点占用、关节和夹爪限位，并按观测桌面检查机器人模型的高度。L1 和 L2 使用 180 秒和 300 秒墙钟限时。程序错误、反馈失效或 Ctrl+C 时停止继续下发，反馈仍新鲜且接口正常时会发送实测关节保持命令。日志区分保持命令发送和硬件停止回执。机械臂需要急停时使用现场硬件急停。当前桌面检查范围不覆盖所有外部障碍物。

在隔离的 Humble 环境用模拟驱动验证过只读检查、ROS 话题重映射、小幅点动和反馈断流。台面保护开启时，L1 仿真完成 3/3。现场先用 `probe` 核对六类实际物料的识别与目的区，再点动和测试完整任务。

复制初始目录后可用 `sha256sum -c SHA256SUMS` 检查文件。清单记录准备目录时的版本，编辑源码和配置后会出现差异。现场标定文件与日志不参与校验。
